# 用三角形把一张图"画"成 SVG 代码（autoresearch 优化后的版本）

`best_solver.py` + `core.c`：给一张参考图和字节预算，输出一份纯矢量 SVG（只有 `<path>` 三角形），
浏览器打开就能看到接近原图的画面。不需要任何模型，普通 CPU 上几秒到几十秒。

## 用法

```bash
python3 best_solver.py input.png outdir --budgets 16000,160000 --time 60 --effort 1
```

- `--budgets`：每个预算输出一份 `outdir/b<预算>.svg`，保证 gzip -9 后不超过这个字节数。
- `--effort`：搜索力度。0.25 约 8 秒，1 约 20 秒，2 约 45 秒（在 5612×240 的图上，M2 Pro 12 核）。
- `--time`：硬性时间上限（秒），到点就停止加形状并输出。
- 依赖：Python 3、numpy、Pillow，以及系统自带的 C 编译器（首次运行自动把 `core.c` 编译成 `core.so`）。

## 和优化前比

分数都是用 Chrome 打开 SVG、1:1 渲染后和原图算的 SSIM（亮度通道），两档预算（gzip 后 16KB、160KB）取平均，
每个设置跑两个随机种子取平均。详细记录见 `results.tsv`（每次实验）、`sweep.tsv`（第一轮）、`sweep_final.tsv`（最终版）。

## 算法做了哪些改动（按贡献排序）

1. 内核改用 C（`core.c`），线程并行；评估改用行前缀和（候选的代价与面积无关）：同样算法快约 25 倍，省下的时间投入搜索。
2. 加大搜索：每个形状多轮"随机候选 + 爬山"。
3. 覆盖率渲染模型：拟合时按面积覆盖计算，与浏览器抗锯齿一致（模型与 Chrome 渲染相差 48–52 dB）。
4. 亮度加权误差：评分的 SSIM 只看亮度，拟合时给亮度误差额外权重（λ=8）。
5. 编码：后两个顶点用相对坐标、省略路径末尾的 z，同一轮的形状按块排序，gzip 更省；颜色量化到 4 的倍数。
6. 几何回拟合（两遍）：全部形状放完后，正向逐个在"前面已定、后面照旧"的条件下重新爬山。
7. 删减再补：按"删除代价"删掉不值它所占字节的形状，用省下的字节补新形状。
8. 颜色回拟合：位置固定时画面对颜色是线性的，逆序做最小二乘。

试过但没用的：透明度改 0.6、每个形状自选透明度（更差）、新形状"笔触"（带宽线段，与三角形混用，更差）、
背景渐变、半像素坐标网格、沿边缘方向生成候选、更粗的颜色量化/调色板、全局模糊或锐化滤镜、禁用细三角形、
阶段 1 形状数、切块数、分配权重、删减再补做两轮。

## 已知的剩余空间

最后几次尝试的收益都在千分之一左右，这套"三角形 + 贪心 + 局部回拟合"的方法基本收敛。
还没做的是"用梯度同时优化所有形状"，按回拟合多扫几遍的收益递减来估计，剩余空间大约千分之几。
同样 160KB，JPEG 的 SSIM 约 0.94，这版是 0.88：三角形表示本身装不下细纹理。
